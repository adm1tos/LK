# LK
Папка vendor - установленные библиотеки с помощью composer
## admin
В admin лежат админские страницы. Пока там только старые VPN настройки, списки заявок и списки пиров
## assets
Там лежат остатки от старого сайта, переделанный стиль под нужды ЛК
## includes
Авторизация, подгрузчик сервисов, подгрузчик .env, шторка и верхушка сайта, вспомогательные файлы в целом
### includes/services
Сервисы управления днс, общения с роутером, общения с гипервизором, управлением настройками, общения с выбранной ВМкой с гипервизора, создания конфигов
## lk_dns
Блок DNS. 
## lk_ssh
Блок SSH. главная страница, список машин, изменение машины
## lk_vpn
Блок VPN. главная страница, главная страница, вспомогательные файлы: скачивание конфига, генерация, отправление запроса на разрешение
## Корневая папка
Главная страница сайта, .env, вызовы авторизаций-регистраций, файлы композера после установки библиотек, еще .htaccess чтобы можно было открывать в браузере только разрешенные файлы

## Установка и настройка

### Запуск через Docker
1. Склонируйте репозиторий.
2. Создайте файл `.env` в корневой папке проекта. За основу можно взять переменные, описанные в `includes/config.php`. Обязательно укажите правильные порты (например, `PROXMOX_PORT=8006`).
3. Выполните команду `docker-compose up -d` (при наличии `docker-compose.yml`) или соберите контейнер вручную, пробросив папку проекта в `/var/www/html` и настроив связку PHP + Apache/Nginx.
4. Установите зависимости через Composer: выполните `composer install` внутри контейнера.
5. Импортируйте структуру базы данных (если есть SQL-дамп) и укажите доступы к ней в вашем `.env`.

### Настройка роутера (MikroTik)
Для корректной работы сервиса `MikrotikService` и управления модулями DNS / VPN:
1. Включите API на роутере: `/ip service set api disabled=no` (или `api-ssl` для защищенного подключения).
2. Создайте отдельного пользователя для панели управления. Ему потребуются права: `read`, `write`, `api` (рекомендуется создать отдельную группу политик безопасности).
3. **Для VPN:** убедитесь, что на роутере уже создан WireGuard интерфейс и настроена соответствующая маршрутизация. Имя интерфейса должно совпадать с `VPN_WG_INTERFACE_NAME` в настройках.

### Настройка гипервизора (Proxmox)
Панель подключается к Proxmox по API для вывода списка виртуальных машин и привязки их IP к DNS-записям:
1. Укажите в `.env` IP-адрес Proxmox, порт (по умолчанию `8006`), пользователя, пароль и realm (чаще всего `pam` или `pve`).
2. У пользователя должны быть права на просмотр машин (например, роли `PVEAuditor` или `PVEVMAdmin`).
3. **Важно для работы DNS-модуля:** Чтобы панель могла автоматически получать IP-адреса виртуальных машин (через QEMU Guest Agent), в настройках самой ВМ (Options) должна быть включена опция **QEMU Guest Agent**, а внутри гостевой ОС установлен и запущен соответствующий сервис (например, `apt install qemu-guest-agent`).

### Настройка авторизации через Яндекс
Для работы входа и регистрации через Yandex OAuth:
1. Перейдите на портал Яндекс.OAuth и зарегистрируйте новое приложение.
2. В разделе «Платформы приложения» выберите «Веб-сервисы» и добавьте Callback URI (Redirect URI). Он должен вести на скрипт обработчика в вашем проекте, например:
   `https://ваш-домен.com/auth/yandex/callback.php`
3. В разделе доступов (scopes) запросите права на получение:
   - Адреса электронной почты
   - Доступа к логину, имени и фамилии, полу
4. Сохраните изменения. Полученные `Client ID` и `Client Secret` добавьте в файл `.env` вашего проекта.
